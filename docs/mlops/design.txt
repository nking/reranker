================================================================================
CPU vs. GPU ROOFLINE & ARITHMETIC INTENSITY ANALYSIS
================================================================================
Definitions:
  - Arithmetic Intensity (I) = FLOPs / (Data Loads + Stores in Bytes)
  - Hardware Ridge Point     = (Peak Hardware FLOPs/sec) / (Peak Bandwidth Bytes/sec)

Hardware Specifications & Ridge Points:
  1. Kaggle CPU (4-core Intel Xeon, AVX2/AVX-512):
     - Peak FP32 Compute:   ~100 GFLOPS (0.10 TFLOPS)
     - Memory Bandwidth:    ~20 GB/s
     - CPU Ridge Point:     100 GFLOPS / 20 GB/s = 5.0 FLOPs/Byte

  2. NVIDIA Tesla T4 GPU (16 GB GDDR6, 320 GB/s Bandwidth):
     - Peak FP32 Compute:   8,100 GFLOPS (8.1 TFLOPS)
       -> FP32 Ridge Point: 8,100 GFLOPS / 320 GB/s = 25.3 FLOPs/Byte
     - Peak FP16 Tensor Core Compute (used by QLoRA fp16=True): 65,000 GFLOPS (65 TFLOPS)
       -> FP16 Ridge Point: 65,000 GFLOPS / 320 GB/s = 203.1 FLOPs/Byte

Operational Arithmetic Intensity of Qwen2.5-0.5B Instruct Supervised Fine-Tune Training:
  - For a batch of B = 16 prompts of length L = 500 tokens, the batch token count
    is M = B * L = 8,000 tokens.
  - For a linear projection W of shape (K, N), GEMM FLOPs = 2 * M * K * N.
  - Bytes transferred = (0.5 * K * N) [4-bit NF4 weights] + 2 * (M * K + M * N) [FP16 activations].
  - Because M = 8,000 >> 1, weight loading is amortized across 8,000 tokens,
    yielding an operational Arithmetic Intensity of I ~ 250 - 400 FLOPs/Byte.
  - Because I > 203.1 FLOPs/Byte, batched training is strictly COMPUTE-BOUND
    on both CPU and T4 GPU:
      * The CPU hits its 100 GFLOPS roof immediately (~35-40 sec/example).
      * 1x T4 operates near its 65,000 GFLOPS FP16 Tensor Core roof (~25-28 ex/sec).
      * 2x T4 DDP doubles compute to 130,000 GFLOPS while synchronizing only
        2.18M trainable parameters (4.3 MB in FP16, taking <2 ms per step over PCIe).
